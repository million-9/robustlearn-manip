# Week 12 — Behavior Cloning Dataset Contract

Issue: #111

## Frozen dataset

The Behavior Cloning pipeline consumes the immutable Week 11
dataset snapshot at `datasets/v0.1/`.

The dataset contains:

| Split | Episodes | Frames |
|---|---:|---:|
| Train | 65 | 2,573 |
| Validation | 15 | 593 |
| Test | 14 | 561 |
| Total | 94 | 3,727 |

The canonical assignments are defined in `splits.json`.

The pipeline reuses the existing frozen-snapshot verification and
deterministic split-validation utilities.

No frozen dataset artifacts are modified during loading.

## Observation representation

The initial BC observation contains 23 float32 features,
concatenated in the following order:

| Features | Dimensions | Units |
|---|---:|---|
| Joint positions | 7 | radians |
| Joint velocities | 7 | radians/second |
| Task-relative position | 3 | metres |
| Wrist force/torque | 6 | newtons / newton-metres |

The task-relative position represents the three-dimensional
relative-position information recorded by the demonstration
collectors.

The observation is state-based. RGB-D images are not used.

All observation features must be finite.

Missing joint velocities are rejected rather than silently
imputed. The frozen v0.1 dataset contains no missing velocities.

## Action representation

Each expert action contains seven float32 values representing
absolute Panda joint-position targets in radians.

This action representation differs from the Cartesian-delta
actions proposed for later robot-learning experiments.

The initial BC implementation follows the actual frozen
dataset schema rather than silently converting command types.

A policy trained on these targets must use a compatible
joint-position command interface during closed-loop execution.

## Scripted versus teleoperation data

The frozen dataset contains:

- 3,694 scripted frames
- 33 teleoperation frames

Both sources record absolute seven-joint position targets.

However, their sampling behavior is different.

Scripted demonstrations are generated by the automated
expert pipeline.

The single teleoperation demonstration is command-triggered
and does not use uniform temporal sampling.

Its observed consecutive-frame intervals range from
approximately 0.52 to 19.04 seconds.

The initial BC dataset treats recorded frames as supervised
observation/action pairs without temporal interpolation,
resampling, or trajectory reconstruction.

Consequently, the loader does not interpret adjacent
teleoperation frames as fixed-rate control steps.

Mixing scripted and teleoperation samples may introduce
distributional differences. Training quality and closed-loop
behavior must be evaluated separately.

## Normalization

Observation and action normalization use feature-wise
training-set mean and population standard deviation.

Statistics are fitted exclusively on the canonical training
split.

Validation and test samples reuse the training statistics;
they never fit their own normalization parameters.

Features with standard deviation less than or equal to
1e-8 use a scale of 1.0.

Actions can be denormalized to recover absolute joint-position
targets in radians.

Future policy checkpoints must retain the corresponding
normalization statistics.

## Deterministic loading

The DataLoader uses an explicitly seeded PyTorch generator.

Training batches are shuffled.

Validation and test batches preserve their canonical order.

The current implementation uses `num_workers=0` and
`drop_last=False`.

Reproducibility is tested using identical and different seeds.

## Dataset limitations

The frozen v0.1 dataset has several limitations:

1. Only one human teleoperation episode is available.
2. All selected episodes are successful.
3. Teleoperation frames are not uniformly sampled.
4. Mixed-source BC performance has not been established.
5. Original production runtime parameters were not fully recovered.

These limitations should be considered when interpreting
offline prediction metrics and closed-loop task success.

## Scope

deterministic batching, and regression coverage.

Neural network architecture, policy training, experiment
tracking, and closed-loop rollout evaluation belong to
subsequent Week 12 issues.
